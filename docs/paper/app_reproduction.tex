\section{Two-rank reproduction and the tile-invariant near shell}
\label{app:reproduction}

The precision campaign was rerun at the paper sizes with two MPI ranks per
case on a node with four V100-SXM2-32GB devices.  Each rank owned one device,
and two cases ran at a time on the disjoint pairs 0,1 and 2,3.  The binary was
built from commit \texttt{b29f55ed4ee787f19e5a74eb8bd7e3a3e84b53ed} with CUDA
12.6 for \texttt{sm\_70}, OpenMPI 4.1.6, parallel HDF5 1.10.10 and openPMD
0.17.1.  The harness is
\texttt{docs/paper/precision-campaign/run\_campaign.py} with
\texttt{--mpi-ranks 2}, one \texttt{--gpu-pairs} entry per worker and
\texttt{--fft-mode distributed}; it pins \texttt{--velocity-bin-edges uniform}
for every case with more than one velocity bin.  The order-12 exact reference
driver ran as a single process and reproduces the committed reference arrays.
The line, hires, large-domain, \texttt{bdata2} and \texttt{multivel} values of
this paper are this run; the scaling and cost campaigns remain the H100
measurements of Section~\ref{sec:scaling}.

The non-near-shell cases reproduce the earlier data: the two-rank
\texttt{line-w4b} worst relative error changes by at most
$1.3\times10^{-13}$ over all 56 rows, \texttt{large1} changes the field by at
most $2\times10^{-10}$ of its peak, and the inner \texttt{line-gamma} rings
are unchanged.

The earlier H100 near-shell values came from a binary before
\texttt{e8d082f} whose correction was a per-tile local-FFT mesh subtraction.
The corrected region was the tile support, so the field depended on the tile
edge; in that path a tile $4$ versus tile $8$ run on the same input differs by
$82.7\%$ of the peak field.  The current operator evaluates the subtraction per
(source, node) pair and blends it by observer distance, so the result is
tile-invariant.  A one-rank control on the current binary reproduces the
two-rank field to $10^{-9}$ relative, and a tile $4$ versus tile $8$ run
agrees, so the differences are not an MPI or tile artifact.  The current code
is the paper of record.

The change is a trade-off, not a uniform improvement.  The far field, the
inner rings and the large-domain slices are unchanged.  At high $\gamma$ and
at oblique incidence the current near-shell error is larger in the beamed
peaks: the worst \texttt{hires} error rises from $1.590$ to $3.442$ at
$\gamma=50$ and from $3.490$ to $5.988$ at $\gamma=100$, and the
\texttt{bdata2} electric and magnetic errors rise.  The \texttt{line-gamma}
ring at $48$ cells, $h=0.25$, is a grid-boundary artifact.  At $\gamma=10$
its committed value changes from $2.49\times10^{-1}$ to
$5.31\times10^{-6}$; this is the $\gamma=10$ row only and does not describe
the other $\gamma$ rows.  The ring sits on the grid boundary in the absorbing
region, so it is a boundary artifact, not a validation win, and it is excluded
from Fig.~\ref{fig:gamma-dist} and from the accuracy claims.  The
\texttt{multivel} peaks change slightly with the current code (Table
\ref{tab:multivel}).

The archived \texttt{var1b} input is not in the repository, so that case was
not rerun.  Its H100 figures and the $1.4\%$ arbiter comparison remain in
Appendix~\ref{app:multivel} and are marked not comparable to the current-code
values.
