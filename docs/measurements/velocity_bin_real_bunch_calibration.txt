Real-bunch velocity-bin calibration (region-aware in-bunch metric)
==================================================================

Bunch: particles_000000.bp5, species b, 49931 particles, mean gamma 490.3
  (rel |u| spread 1.69e-2, max angle 0.0253 rad, 0.78 deg divergence)
Field: makeGrid 298x122x318, cell 2e-7 m.  Beam axis: lab +y.

FORMULA DECISION
----------------
The shipped angular term is C_ang * Delta_theta^2 (squared), with C_ang = 1
(kAngularModelConstant).  It is NOT gamma * Delta_theta (that worst case was
retired in the W37 calibration).  The B=1 real-bunch model_sum 1.1363e-3
decomposes into the angular term 6.4e-4 (C_ang * theta^2) plus the energy term
4.9e-4 (2 * maxDelta_gamma/gamma, the per-particle gamma deviation, up to
1.3e-1); it is not gamma * theta / 2.  The table, the Types.hpp comment, and
this document state the same formula.

ARBITER (the truth): exact Liénard-Wiechert direct-sum reference
---------------------------------------------------------------
The arbiter computes the field at in-bunch probe nodes by direct summation of
the Liénard-Wiechert field of EVERY particle (no proxy, no fitted kernel, no
TSC convolution), at the actual per-particle gamma distribution, and reports
the per-component relative error normalised by the reference amplitude at each
probe node (maximum over nodes), plus the absolute By error.  Probe nodes: the
bunch core plus points at 2, 5 and 10 sigma in each transverse (lab x, z)
direction (13 nodes).  Reproducible from the repository:

  python3 tools/velocity-bins/arbiter_in_bunch.py \
      --bunch <bunch.bp5-or-txt> --species b --bins 1,2,4,8,16,32,64,256
  (CMake test: VelocityBinsArbiterReference)

CONVERGENCE AND SATURATION
--------------------------
The tolerance (1e-3) is NOT reached by any component at any box count up to
256.  The per-node relative error is dominated by the beam-axis components
(Ez ~ 6.7e9, Bx ~ 22 T at the core, versus By only 0.35 T) and the core 1/r
singularity (nearby particles dominate the core field, so replacing their
velocities by a box representative is a large error that does not vanish as
the boxes refine).  The absolute in-bunch By error saturates: 3.5e-1 T at 1
box, 2.2e-1 T at 16-32 boxes, 6.4e-2 T at 256 boxes (it does not reach
3-7e-4 T, and it does not converge to zero within the cap).

Cause (with numbers): a GENUINE LIMIT OF THE VELOCITY-BINNING MODEL at
gamma 490, not the reference accuracy and not the TSC convolution of the
reference (the arbiter uses a direct sum, no convolution).  The binning
groups particles by velocity direction; the beam-axis field (Ez, Bx) and the
core near-field are set by the per-particle gamma (energy) and the
longitudinal position, which the transverse velocity binning does not resolve.
The per-particle gamma deviation (maxDelta_gamma/gamma ~ 1.3e-1) is the
node-bounded energy term in the shipped model, and it does not shrink to
1e-3 as the boxes refine.

CONSEQUENCE AND THE AUTO POLICY
-------------------------------
Because the in-bunch error saturates above the tolerance (and 256 boxes is 256
field solves, which no production run accepts), the auto policy (inBunchCriterion
on) does NOT return the cap.  It returns the smallest box count after which the
in-bunch model error no longer improves by at least kSaturationImprovement (0.5,
i.e. "a doubling cut the error by at least half") per doubling: the saturation
count.  The achieved accuracy (modelError at that count) is reported as a
diagnostic.  If a count does meet the tolerance within the cap (a bunch with a
small per-particle gamma deviation, like the synthetic realBunchLike), the auto
policy returns that count instead.  This is the arbiter requirement: do not
return 256; report the saturation count and the achieved accuracy.

REPRODUCIBILITY OF THE TSC-CONVOLVED REGION TABLE
-------------------------------------------------
(Secondary) The TSC-convolved continuum reference (indfield, order 8) peak-
normalised region table is regenerated by:
  python3 tools/velocity-bins/measure_region_bins.py \
      --bunch <bunch.bp5> --species b --cell 2e-7 \
      --origin 1.5149e-05,9.7255e-05,1.2683e-05 --grid 298,122,318 \
      --bins 1,2,4,8,16,64,256 --cell-region 163,70,23 --cell-radius 3 \
      --subset 391
  (CMake test: VelocityBinsRegionReference)
That table normalises by the in-bunch reference peak per component and was the
basis of the earlier peak-normalised analysis; the arbiter (above) is the
direct-sum truth it is checked against.
