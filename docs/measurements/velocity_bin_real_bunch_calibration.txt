Real-bunch velocity-bin calibration (region-aware in-bunch metric)
==================================================================

Bunch: particles_000000.bp5, species b, 49932 particles, mean gamma 490.3
  (rel |u| spread 1.69e-2, max angle 0.0253 rad, 0.78 deg divergence)
Field: makeGrid 298x122x318, cell 2e-7 m.

FORMULA DECISION
----------------
The shipped angular term is C_ang * Delta_theta_b^2 (squared), with
C_ang = 1 (kAngularModelConstant).  This is what the code computes (see
VelocityBinning.cpp, evaluateSplit: "angular = kAngularModelConstant * ... *
angle * angle") and what the W37 angular calibration
(velocity_bin_angular_calibration.txt) uses.  The angular term is
NOT gamma * Delta_theta: that worst case was retired in the W37 calibration
because it over-predicted the measured superposition-cancellation error by
~gamma/Delta_theta (for the real bunch, gamma * theta = 12.4 vs the squared
term 6.4e-4, a ~1.9e4 factor).  Any document that states gamma * theta for
the shipped angular term is wrong and has been corrected.

Model decomposition at B=1 (the shipped model, evaluated on the real bunch):
  angular  (C_ang * maxAngle^2)        = 6.42e-04
  energy   (2 * maxDelta_gamma/gamma)  = 4.94e-04   (the per-particle
                                                    gamma deviation, up to
                                                    1.3e-1 for this bunch)
  modelSum (angular + energy)          = 1.1363e-03
So the B=1 model_sum 1.136e-3 in the table below is the SHIPPED formula
value (the energy term, not the angular term, dominates at B=1 for this
bunch).  It is not "gamma * theta / 2" (which would be 6.2); it is
C_ang*theta^2 + 2*delta_gamma/gamma.

REPRODUCIBILITY
---------------
The measured in-bunch table (below) is regenerated from the repository by the
runnable tool target "picBunchBunchBinsRegion" (added this commit,
tools/velocity-bins/measure_region_bins.py), which wraps the committed
TSC-convolved continuum reference indfield.integrate_point (order 8).  The
exact command for the real bunch:

  python3 tools/velocity-bins/measure_region_bins.py \
      --bunch <bunch.bp5> --species b --cell 2e-7 \
      --origin 1.5149e-05,9.7255e-05,1.2683e-05 \
      --grid 298,122,318 \
      --bins 1,2,4,8,16,64,256 \
      --cell-region 163,70,23 --cell-radius 3 \
      --subset 391 --k 128

  --cell-region 163,70,23 is the By-peak cell (x,y,z, x-fastest); --cell-radius
  3 gives the 27-cell patch; --subset 391 is the stratified particle subset
  (of 49932) that bounds the reference cost.  The tool prints the same
  peak-normalised per-component table as below.  (The per-particle continuum
  reference is slow, ~20 ms/particle/cell in-bunch, so the full 298x122x318
  x 49932 run is intractable; the 27-cell patch x 391-particle subset is the
  validated region.)

Metric: TSC-convolved continuum reference (indfield, order 8), per-particle
  (T) vs binned (Tb), at the 27-cell in-bunch patch around the By-peak cell,
  391-particle stratified subset (k=128), weight*charge, beam-frame box split.
  Normalised by the in-bunch PEAK of the reference per component (peak-
  normalised, NOT per-cell). Driver = max over E and B in the in-bunch region.

The in-bunch peak-normalised driver is amplified by ~gamma relative to the
far-field angular model (the transverse B and in-bunch E peaks are suppressed
by ~1/gamma for a relativistic beam); the gamma-amplified in-bunch criterion
(kInBunchAngularGammaAmplification = 2.2) drives the auto policy to the cap
for this bunch.

SATURATION / FLOOR OF THE MEASURED TABLE
----------------------------------------
The measured table above is peak-normalised in the in-bunch region and is
bounded below by the finite in-bunch reference peaks (By 8.8e-4 T, Ey
1.95e5 V/m): the peak-normalised relative error cannot fall below
|Tb-T|/peak, and the continuum reference (indfield order 8) itself has a
finite TSC-convolution accuracy, so the measured in-bunch relative error has
a floor well above 1e-3 for this beam (measured driver 0.19 at B=256).  This
floor is NOT the binning error: it is the limit of the peak-normalised metric
on tiny in-bunch peaks plus the reference's own convolution accuracy.  The
consequence is that the peak-normalised in-bunch metric cannot resolve
in-bunch errors below this floor, so it cannot certify a 1e-3 in-bunch
requirement for a gamma ~ 490 beam; the auto policy therefore returns the cap
(the count that minimises the in-bunch error) with a diagnostic rather than
claiming 1e-3.

This is distinct from the W37 far-field angular-calibration floor: that record
(velocity_bin_angular_calibration.txt) is calibrated on synthetic gamma-10
bunches where the far-field Liénard-Wiechert proxy reference is accurate, and
its model sums (not a measured floor) are what the far-field criterion uses.
The in-bunch region is chosen (the 27-cell patch at the By peak) so the far-
field proxy floor does not mask the in-bunch error: the patch is inside the
bunch, where the TSC-convolved continuum reference is the correct kernel and
the peak-normalisation is against in-bunch peaks, not far-field ones.
